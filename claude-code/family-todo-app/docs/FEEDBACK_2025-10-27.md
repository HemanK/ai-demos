### 4.3 Default Due Date Behavior
**Requirement**: If due-date is not specified or cannot be inferred, default to **"this week"** (Friday of current week).

**Implementation**:
```javascript
// In SmartParser or Date Extractor tool
function inferDueDate(text, extractedDate) {
  if (extractedDate) return extractedDate;

  // Default to Friday of current week
  const today = new Date();
  const friday = new Date(today);
  friday.setDate(today.getDate() + (5 - today.getDay()));

  return friday;
}
```

### 5.6 AI Failure Modes & Mitigation Strategies
**ADD NEW SECTION**: "AI Failure Modes & Mitigation"

**Context**:
Many AI projects fail due to:
- Over-reliance on AI accuracy
- Poor error handling
- Unexpected edge cases
- User trust erosion
- Cost overruns
- Regulatory/privacy issues

**Our Project's Failure Modes**:

| Failure Mode | Likelihood | Impact | Mitigation |
|--------------|------------|--------|------------|
| AI parsing errors | High | Medium | Manual entry fallback, user can edit |
| API rate limits | Medium | High | Local queue, retry logic, graceful degradation |
| Incorrect categorization | Medium | Low | Easy to change, feedback collection |
| High API costs | Low | Medium | Token tracking, caching, model tiering |
| localStorage data loss | Low | High | Export reminders, auto-export, cloud backup (roadmap) |
| Browser compatibility | Medium | Medium | Progressive enhancement, polyfills |
| Slow AI response | Medium | Medium | Loading states, async processing, timeouts |
| Privacy concerns | Low | High | Local processing, clear disclosure, no PII to AI |
| User rejection of AI | Low | Medium | Make AI optional, show value quickly |
| Model deprecation | Low | Medium | Provider abstraction, version pinning |

**Mitigation Strategies**:

1. **Graceful Degradation**:
   - All features work without AI (manual mode)
   - AI enhances but doesn't block core functionality
   - Clear fallback paths

2. **User Trust**:
   - Transparent about what AI does
   - Easy to override AI suggestions
   - Feedback collection shows we care about accuracy

3. **Cost Control**:
   - Token tracking and budgets
   - Caching for repeated queries
   - Model tiering (Haiku for simple tasks)
   - User control over AI usage

4. **Data Safety**:
   - localStorage + export (user controls data)
   - No PII sent to AI (task titles only, not personal details)
   - Roadmap for backend with encryption

5. **Testing**:
   - Unit tests for all critical paths
   - AI behavior tests (prompt engineering validation)
   - Edge case handling (empty inputs, special characters)
   - Performance testing at scale (1000+ tasks)

**Success Indicators (Pre-Launch)**:
- ✅ All features work without AI enabled
- ✅ >95% test coverage on core functionality
- ✅ Tested with 1000+ tasks in localStorage
- ✅ Error handling for all AI failure modes
- ✅ User feedback mechanism functional
- ✅ Export/import tested successfully

### 5.7 Storage Concerns & Backend Enhancement Path
**ADD Section**: "Storage Strategy & Evolution"

**Current Approach**: localStorage
- **Pros**: Simple, fast, no backend needed, works offline
- **Cons**: Browser-specific, can be cleared, no sync across devices, ~5-10MB limit

**Concerns**:
- Data loss if browser cache cleared
- No automatic backup
- No cross-device sync (iPhone ↔ Mac)
- Difficult for family members on different devices

**Mitigation (V1.0)**:
- Export to JSON (weekly reminder)
- Import from JSON (easy restore)
- Auto-export to downloads folder (optional)
- Clear messaging about localStorage limitations

**Evolution Path**:

**V1.1**: Google Sheets Backend (Optional)
- **Why Google Sheets**: Many families already use it, familiar, free, simple API
- **Implementation**: Sheet as database (one row per task)
- **Sync**: Manual sync button or auto-sync every 5 minutes
- **Privacy**: User's own Google account, data stays with them
- **Effort**: ~8-12 hours for Google Sheets API integration

**V1.5**: Dedicated Backend (Firebase/Supabase)
- Real-time sync across devices
- User authentication
- Better data structure than Sheets
- Push notifications (task reminders)
- Collaborative editing (multiple family members at once)

**V2.0**: Self-Hosted Option
- Docker container with SQLite/PostgreSQL
- For privacy-conscious users
- Full control over data

**Recommendation for V1.0**:
- ✅ **Ship with localStorage + export/import**
- ✅ **Document known limitations**
- ✅ **Collect user feedback** on storage needs
- ✅ **Plan Google Sheets integration** (show roadmap)

**Add to PRD**:
- Storage evolution section
- Known limitations of localStorage
- Roadmap for backend enhancements
- User education about export/import
